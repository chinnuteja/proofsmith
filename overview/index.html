From supplied check to recorded decision

One check. Two source snapshots. Inspectable evidence.

01 / QUALIFY & FREEZE

Establish the failure first

Require stable eligible failures in at least 8 of 10 original runs. Bind the check, source, and build recipe; retain its identity before repair.

02 / GATE THE CANDIDATE

Replay on disposable copies

Run the original and candidate 20 times each. Require at least 16 matching original failures and zero candidate failures for a verified decision.

03 / REVIEW & SHARE

Keep the decision portable

Inspect HTML and JSON receipts, raw logs, frozen inputs, and integrity manifests. Copy the full evidence directory to preserve its links.

Supplied regression · authored controls

Passing smoke tests can leave a quota bug intact.

A C++ quota reservation must reject amounts above remaining capacity. Near UINT64_MAX, adding used + amount can wrap. An authored partial patch adds a size cutoff but retains the unsafe addition. It passes the ordinary smoke tests; the frozen check still reproduces the failure.

// Precondition: used <= limit
if (amount > limit - used) return false;
used += amount;
return true;

The supplied fixed control checks remaining capacity before adding. These are controlled examples, separate from model scores.

VERIFIED / EXIT 0

Target reproduced; candidate passed

The original meets the reproduction threshold and the candidate passes every recorded run of the frozen check.

REJECTED / EXIT 1

The target still fires

The same target failure is observed on the proposed fix. Review the matching failure evidence.

INCONCLUSIVE / EXIT 2

Evidence cannot support approval

Build failures, weak reproduction, input mismatches, or unexpected failures leave the decision unresolved.

Scope of the decision: a receipt records the supplied check and finite executions. It is not a proof of general correctness, complete test coverage, or absence of other defects.

Install and run offline

Bring your own original, candidate, and check.

Use Linux or WSL with Python 3.12+, clang/LLVM, CMake, and bubblewrap. Clone the source and install in a virtual environment:

git clone https://github.com/chinnuteja/proofsmith
cd proofsmith
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev,mcp]'
bash scripts/ci_gate.sh /tmp/proofsmith-first-check

Choose a new output directory. This supplied installation fixture exercises qualification and the fixed/unfixed gates with the real compiler.

For your own patch, seal the regression, retain its pre-patch identity, then gate a separate candidate using the original build recipe.

ByteAsk repair acceptance: five synthetic cases

The real ByteAsk CLI, using gpt-5.4, correctly repaired all five authored cases. All candidates passed 5,419 independent evaluator checks and the frozen gates preserved all five correct acceptances. No advantage over ByteAsk was demonstrated in this pilot.

The fifteen authored controls above are excluded from model scores. This comparison measures final acceptance of the same repairs, not improved repair generation. Five synthetic cases cannot establish general superiority.

Earlier research and additional limits

The earlier automatic verifier-generation pilot had zero fail-to-pass successes in twelve observations and seven historical token-limit violations. The repaired protocol has no new paid observations. The real ByteAsk run also retained errors for unavailable optional native-analysis dependencies. These outcomes remain in the repository.
